# 8주 완성 교재 운영 연결

웹 DB가 구매·첨삭 사용 횟수의 기준입니다. 기존 Google Sheet는 온보딩과 D-14/D-7 이용기한 알림에 사용합니다. 사진은 운영자가 웹의 직접 업로드 화면에 넣습니다.

## 구매 데이터 입력

웹의 학부모 화면에서 `+ 8주 완성 구매`를 열고, 시트의 A:O 고객 행이나 Markdown 표 행을 그대로 붙여넣습니다. 표 구분선과 뒤에 붙은 빈 열은 무시합니다. 미리보기에서 이름, 교재단계, 구매유형, 남은 횟수, 이용기한을 확인한 뒤 저장합니다. 이미 있는 매주 3단어 고객은 정규화한 연락처로 연결합니다. 제공된 예시 행은 운영 DB에 넣지 않습니다.

동일 연락처·교재단계·구매유형·구매일의 재입력은 중복으로 건너뜁니다. 실제로 같은 날 동일한 상품을 두 번 구매했다면 현재 시트 열만으로 구별할 수 없으므로 주문번호 같은 별도 식별값을 추가해야 합니다.

## 시트 잔여 횟수 연동

1. 시트의 모든 기존 구매 행을 웹 DB로 먼저 가져와 총횟수·기존 사용횟수·이용기한을 대조합니다. 시트에만 있는 행이 있으면 동기화는 중단됩니다.
2. 운영 중인 Apps Script 프로젝트에 `Sync.gs`를 추가합니다. 스크립트 속성에 `WEB_API_BASE`와 `WEB_ADMIN_PASSWORD`를 지정합니다.
3. 기존 이용기한 알림 함수에서 고객 행을 읽기 직전에 `syncEightWeekBalancesFromWeb()`를 호출합니다. 사용완료횟수(J열)만 DB 값으로 갱신하고 남은횟수(K열)는 `총횟수-사용완료횟수` 수식을 유지합니다. 시트가 알림 메시지를 보내는 기존 역할은 그대로 둡니다.
4. 시트의 시간대가 서울과 다를 수 있으므로 구매일은 시트에 설정된 시간대로 해석합니다. 알림 트리거가 의도한 한국 시간에 실행되는지도 별도로 확인합니다.

`Sync.gs`는 시트의 고정 열 위치와 탭 이름 `8주완성 고객관리`를 사용합니다. 열 순서나 탭 이름이 바뀌면 코드를 조정해야 합니다. 현재 동기화 코드는 배포용 준비 파일이며 실제 시트 프로젝트에는 설치되지 않았습니다.
